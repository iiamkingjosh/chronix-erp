Data Tables on Mobile: How should they behave?

Chronix has many dense tables (employees, invoices, tickets, projects…). On a 375px screen a 7-column table won't fit. Pick the approach you prefer.

A

Horizontal Scroll (Recommended)

Tables stay as tables but scroll horizontally inside a container. A subtle fade-shadow on the right edge hints there's more content. No layout restructuring needed.

EMP # EMPLOYEE ROLE DEPT
CTL001 John Doe Staff BRAND
← swipe →

Pros

  • Least code change
  • Data stays scannable
  • Familiar pattern

Cons

  • Discovery of scroll
B

Card List on Mobile

On mobile, each table row becomes a compact card showing only the key fields (name, status, amount). Tap a card to open the detail view.

John Doe Active

Pros

  • Very mobile-native
  • Easy to tap

Cons

  • More code per page
  • Less data visible
  • Inconsistent with desktop
C

Hybrid: Scroll + Key Columns Only

Tables scroll horizontally but secondary columns (e.g. "Joined date", "Actions") are hidden on mobile via hidden sm:table-cell. Only the most important 3–4 columns show.

CTL001 John Doe Active
CTL002 Jane Smith Suspended

Pros

  • Clean on small screens
  • No horizontal scroll needed

Cons

  • Hidden data may confuse
  • Actions hard to reach
